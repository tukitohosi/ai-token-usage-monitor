# v1.1.0 升级说明

本次修复长请求仍按基础价估算、导致项目 API 价值偏低的问题。多个对话可以共用一个工作区和模型，应用会为每次请求单独选档，再把金额加到项目和当天的总额中。

## 如何估算长请求

- 完整输入包括普通输入、缓存读取和缓存写入。恰好达到门槛时使用基础档，超过门槛时对整次请求的输入与缓存应用输入倍率，对输出应用输出倍率。高峰加价可按时段叠加。
- 例如，门槛为 272,000 时，三次各 100,000 输入的请求分别使用基础价。一次请求含 100,000 普通输入和 180,000 缓存读取时，完整输入为 280,000，这次请求使用长上下文价。
- Claude Code 合并同一回复的流式用量记录后计价。对于只能取得汇总、无法核实单次输入的历史，应用显示“长上下文档位未确认”，有基础价时按基础档估算。未填写基础单价的用量继续显示未定价。

## 如何启用

1. 打开“模型定价”，为模型填写长上下文门槛、输入倍率和输出倍率，或选择“从本机 Claude Code 导入长上下文规则”。
2. 导入会读取本机启用的 cc-statusline 状态栏预设及用户覆盖，并把匹配的模型规则放入草稿。已有单价、币种和高峰设置保留。
3. 选择“保存价格并重算”。总览、项目下钻、每日明细和导出都汇总同一套逐请求金额。旧索引可从仍在本机的日志补读，已采集的历史用量会保留。

定价 JSON 现以版本 2 导出，携带长上下文规则。导入版本 1 的文件时，已配置的模型保留原有长上下文规则。

## Codex 用量采集

补充可核实的 Codex 桌面用量记录和当前账号可见的 Work 用量，并在界面提示采集范围。缺少完整请求明细的汇总记录沿用基础估值。
